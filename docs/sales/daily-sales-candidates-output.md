# 毎朝営業候補レポート出力仕様

## 目的

毎朝9:00にHermes Agentが作成する営業候補10件を、Hermes local出力だけでなく、後から確認できるMarkdownレポートとして保存する。

## 保存先

```text
docs/reports/sales/daily/YYYY-MM-DD-daily-sales-candidates.md
```

## ファイル名ルール

- `YYYY-MM-DD` は実行日
- 例: `2026-05-29-daily-sales-candidates.md`
- 既に同名ファイルがある場合は上書きせず、必要に応じて末尾に `-v2` を付ける
- 例: `2026-05-29-daily-sales-candidates-v2.md`

## レポートに含める内容

以下を必ず含める。

1. 実行日
2. 実行時刻
3. 対象地域
4. 対象業態
5. 今日の営業候補一覧
6. 各候補の詳細
   - 店名
   - 業態
   - 地域
   - 個人店・小規模店らしい理由
   - チェーン/FCではなさそうと判断した理由
   - 連絡導線
   - 送信前確認URL/SNS
   - 営業不可・DM不可・問い合わせ不可の確認状況
   - DM文面案
   - 手動コメント案
   - メール件名案
   - メール本文案
   - スプレッドシート上の推奨ステータス
   - Instagram URL
   - Instagramユーザー名
   - Instagramフォロワー数
   - フォロワー区分
   - Instagram運用課題
   - Instagram営業優先度
   - Instagram営業切り口
7. 今日の推奨送信順
8. 人間が送信前に確認するチェックリスト
9. 候補不足がある場合の理由
10. 除外した候補がある場合の除外理由
11. 次アクション

## 候補取得ソースの優先順位

毎朝9:00の候補作成では、以下の順番で確認する。

1. `data/prospects/*.json` を横断確認する
2. ファイル名に `instagram` または `expanded-area` が含まれるJSONを優先する
3. 更新日が新しいJSONを優先する
4. `docs/reports/sales/research/*.md` の直近リサーチレポートも確認する
5. 既存JSONとリサーチレポートだけで10件に満たない場合はWeb補助リサーチを行う

Web補助リサーチで見つけた候補は `新規候補` として扱う。スプレッドシートには自動投入しない。営業送信も自動化しない。

Instagramアカウントが確認できる候補を優先する。A候補はフォロワー5,000人未満を公開情報で確認済みで、店舗または事業単独アカウント、連絡導線、プロフィール/投稿/予約導線/実績訴求の改善余地が確認できる小規模店舗・中小規模事業者を中心にする。フォロワー数不明はB候補、5,000人以上は原則Cまたは除外にする。

フォロワー数が不明な場合は `未確認` / `unknown` と記録し、推測で埋めない。Instagram DM文案やコメント案は人間が手動送信/投稿するための下書きに限定し、自動送信や自動コメントは行わない。

## 候補分類

Markdownレポートでは、候補を以下に分ける。

- 送信候補A
- 条件付き候補
- 新規候補
- 除外・後回し候補
- 候補不足

候補不足がある場合は、既存JSON、リサーチレポート、Web補助リサーチのどこで不足したかを具体的に記録する。

## 禁止事項

- 営業メールを送らない
- SNS DMを送らない
- 問い合わせフォームを送らない
- スプレッドシートを自動更新しない
- `scripts/sheets/send-prospects.mjs` を実行しない
- `SECRET_TOKEN`、Webhook URL、APIキー、認証情報を記載しない
- 架空URL、架空実績、成果保証表現を記載しない

## 確認方法

毎朝9:00以降、以下のパスを確認する。

```text
docs/reports/sales/daily/
```

またはHermesに以下を聞く。

```text
今日の daily-sales-candidates レポートを表示してください。
```


## 重複除外

日次候補出力前に、Google Sheets CSVまたは重複除外台帳、既存JSON、既存レポートを照合し、既存候補・検収済み・送信済み・除外済み店舗を再出力しない。緊急時以外はCSV未設置で候補生成しない。

## 成功条件と補完判定

日次営業候補生成では、ファイル存在だけで完了扱いにしない。当日JSONまたはMarkdownレポートの本文から候補数を確認し、候補0件は成功扱いにしない。

- 目標: A/B候補10件
- 最低実用ライン: A/B候補8件以上
- 0件: `失敗/未達` として `emergency_refill_mode` を実行する
- 1〜7件: `候補不足` として補完対象にする
- 8〜9件: 実用可だが補完候補を追加で探す
- 10件以上: 完了

12:30 / 14:00補完チェックでは、当日JSON、当日レポート、候補件数、A候補数、B候補数、C/除外候補の混入、重複候補、候補不足の有無を確認する。

## 探索Tierと緊急補完

通常探索で10件に満たない場合は、探索Tierを順に広げる。

1. Tier 1 業種拡張: ボディケア、小規模エステ、サウナ/温浴、スポーツスクール、キッズスクール、料理教室、花屋、雑貨店、セレクトショップ、ベーカリー、テイクアウト専門店、小規模宿泊、地域密着施工会社、採用に困っていそうな中小企業を追加する
2. Tier 2 エリア拡張: さいたま市全域、川越、所沢、志木、新座、ふじみ野、三郷、八潮、春日部、松戸、柏、市川、船橋、浦安、千葉市、横浜市北部、川崎市、東京23区全域へ広げる
3. Tier 3 フォロワー条件の近似許容: フォロワー数不明でもInstagram URLあり、5,000人以上と断定できない候補はB候補として許容する
4. Tier 4 近接条件の候補: Instagram運用や導線が弱く、地域密着型で営業対象として自然な候補をB候補として許容する

`emergency_refill_mode` では、CSVがなくても中止せず `CSV未設置のため完全照合未実施` と明記する。ローカルJSON、既存レポート、台帳で最大限重複除外し、最低8件、目標10件を出力する。Sheets投入、営業送信、Instagram DM、コメント、フォーム送信は行わない。

## レポート追加項目

日次レポートには、候補数、A候補数、B候補数、C/除外候補数、フォロワー5,000人未満確認済み件数、フォロワー数不明件数、Instagram URL確認率、重複除外件数、使用した探索Tier、候補不足時に試した拡張条件、CSV有無を必ず含める。
