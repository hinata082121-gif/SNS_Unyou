# Gmail Contact Basis Review Workflow

Date: 2026-06-30

## Current Blocker

Production infrastructure is ready, but the current source candidates do not have reviewed contact basis metadata. The expected blocker is:

- `operationalCandidateReady=false`
- `candidateBlockedReasons=["eligible_basis_count_below_30"]`

This workflow is for human review. It does not auto-approve unknown candidates.

## Review Queue

The review tab is controlled by:

- Property: `GMAIL_SALES_CONTACT_BASIS_REVIEW_TAB_NAME`
- Default tab: `Gmail_Contact_Basis_Review`

Run `installGmailSalesContactBasisReviewWorkflowOnce` only while safe-rest is active:

- `AUTO_SEND_ENABLED=false`
- `LIVE_SEND_ENABLED=false`

The installer creates or migrates the review tab, adds missing columns, configures validation, and sends no Gmail.

## Decisions

`reviewDecision` values:

- `pending`
- `approved`
- `rejected`
- `needs_more_evidence`

`approvedBasisType` values:

- `existing_relationship`
- `explicit_opt_in`
- `valid_business_contact_exception`
- `manual_legal_reviewed`

`suggestedBasisType` is only a hint. It is never applied until a human sets `reviewDecision=approved`, chooses `approvedBasisType`, enters `evidenceNotes`, confirms `optOutAvailable=TRUE`, sets `reviewerLabel`, and sets `reviewedAt`.

## Evidence Requirements

`existing_relationship` requires existing relationship evidence such as a prior inquiry, transaction, meeting, reply, or explicit existing-customer record.

`explicit_opt_in` requires opt-in evidence such as a registration, request, permission record, or opt-in timestamp.

`valid_business_contact_exception` requires business contact evidence, a real source reference, a source type, non-guessed contact, non-private personal contact, and opt-out availability.

`manual_legal_reviewed` requires a reviewer label, reviewed timestamp, and evidence notes. It must not be used for blank bulk completion.

## Hashes And Stale Detection

`sourceReferenceHash` is generated by code from an existing `sourceReference` and `sourceType`. Users do not type the hash directly.

`sourceRowDigest` records the source row state at queue creation. If the source row changes before apply, the row is marked stale and is not applied.

## Refresh And Apply

`refreshGmailSalesContactBasisReviewQueueOnce` reads the source sheet and upserts candidates requiring review. Existing review decisions and applied rows are preserved.

`applyApprovedGmailSalesContactBasisReviewsOnce` applies only valid approved rows. It writes only contact basis columns back to the source sheet, validates read-back, and rolls back the batch if read-back fails.

Suspicious bulk approval patterns are blocked. The workflow does not include any approve-all function.

## Operational Gate

The current daily prepare gate remains unchanged:

- `eligibleAfterBasisCheckCount>=30`

If fewer than 30 candidates have valid approved contact basis, the normal daily prepare must not start.

## Production Procedure

1. Replace Apps Script `Code.gs` with the latest local version.
2. Save.
3. Run `setGmailSalesSafeRestPropertiesOnce` once.
4. Run `installGmailSalesContactBasisReviewWorkflowOnce` once.
5. Run `refreshGmailSalesContactBasisReviewQueueOnce` once.
6. Run `inspectGmailSalesContactBasisReviewQueue`.
7. Open `Gmail_Contact_Basis_Review`.
8. Review high-priority rows first.
9. Set `reviewDecision`.
10. For approved rows, set `approvedBasisType`.
11. Enter `evidenceNotes`.
12. Confirm `optOutAvailable=TRUE` only when supported by evidence.
13. Set `reviewerLabel`.
14. Set `reviewedAt`.
15. Review at least 30 rows with defensible evidence.
16. Run `applyApprovedGmailSalesContactBasisReviewsOnce` once.
17. Run `inspectGmailSalesContactBasisReviewQueue`.
18. Run `inspectGmailSalesContactBasisCoverage`.
19. Run `inspectGmailSalesDeploymentReadiness`.
20. Confirm `deploymentReady=true`.
21. Confirm `operationalCandidateReady=true`.
22. Confirm `approvedBasisCount>=30`.
23. Confirm `eligibleAfterBasisCheckCount>=30`.
24. Run `inspectGmailSalesProductionTriggers`.
25. Confirm one control loop trigger and zero old send triggers.
26. Do not run the send authority directly.
27. Let the next control loop prepare the daily batch.

The workflow logs aggregate JSON only. It must not log email addresses, business names, source URLs, message bodies, Sheet IDs, Script IDs, tokens, or secrets.
