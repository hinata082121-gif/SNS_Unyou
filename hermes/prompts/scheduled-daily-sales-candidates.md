# 毎日12時 営業候補整理プロンプト

## 目的

毎日12:00に、その日に人間が確認・手動送信するICHI Socialの営業候補10件を整理する。

## 絶対条件

- 営業メール、SNS DM、問い合わせフォーム送信は絶対に行わない
- Googleスプレッドシートの自動更新も行わない
- 候補整理、送信前確認ポイント、DM文面案、メール文面案だけを作る
- 候補の質が低い場合は、無理に10件出さず `候補不足` と報告する

## 対象条件

- ステータス `未検収` または `検収済` を優先
- 相性スコアAを優先
- すでに `送信済`、`返信あり`、`商談化`、`反応なしクローズ`、`除外` の候補は対象外
- チェーン、FC、多店舗ブランド、本部運営色が強い店舗、総合SNSしかない店舗は除外
- 店舗単独の公式サイトまたはInstagramがある候補を優先
- Instagramアカウントが確認でき、フォロワー5,000人未満の候補を営業対象にする
- フォロワー2,000人以下は引き続き有望だが必須条件ではない
- フォロワー数が不明な場合は `未確認` / `unknown` とし、B候補として扱う。推測で埋めない
- フォロワー5,000人以上が確認できた場合は原則除外またはC候補にする
- 問い合わせフォーム、メール、Instagram DM、LINE、電話などの連絡導線がある候補を優先
- 営業不可、DM不可、問い合わせ不可の記載がある候補は除外
- 実在確認が弱い候補、出典URLが一覧ページのみの候補は除外

## 候補取得ソース

毎朝9:00の営業候補は、以下の順番で確認する。既存JSONだけを見て即0件で終了しない。

### 1. 既存の見込み客JSON

確認対象:

- `data/prospects/*.json`

優先:

- ファイル名に `expanded-area` が含まれるもの
- ファイル名に `instagram` が含まれるもの
- 更新日が新しいもの
- Instagram URL、フォロワー数、店舗単独SNS、連絡導線が記録されているもの
- ステータスが `未検収` または `検収済` のもの

除外:

- `送信済`
- `返信あり`
- `商談化`
- `反応なしクローズ`
- `除外`
- チェーン/FC/多店舗ブランドの可能性が高い
- フォロワー5,000人以上で既にInstagram運用が強い
- 連絡導線がない
- 営業不可/DM不可/問い合わせ不可の記載がある

### 2. 直近のリサーチレポート

確認対象:

- `docs/reports/sales/research/*.md`

優先:

- 直近14日以内のもの
- 個人店・小規模店舗と判断されているもの
- 公式サイトまたは店舗単独SNSが確認されているもの
- 連絡導線が確認されているもの

## 重複除外の必須手順

候補選定前に、Google Sheets CSVまたは重複除外台帳、既存JSON、既存レポートを横断して照合する。ステータスが `未検収`、`検収済`、`除外`、`送信済`、`返信あり`、`商談化`、`反応なしクローズ`、`未送信` の店舗は再出力しない。

通常運用ではCSVまたは重複除外台帳がない場合は候補生成を停止する。緊急時のみ、人間が明示的に許可した場合に限り、CSV未参照の制約を明記してローカルJSON/レポート由来の暫定台帳で継続する。

新規候補は、同一業種が10件中5件、同一エリアが10件中5件を超えないようにする。C候補は営業対象に含めない。

## 毎朝レポートの分類

Markdownレポートには、以下の分類を必ず含める。

### 送信候補A

条件:

- 個人店・小規模店舗らしい
- 店舗単独SNSまたは公式サイトがある
- Instagramフォロワー数が5,000人未満を公開情報で確認済み、または手動確認でA候補にできる根拠がある
- 連絡導線がある
- 営業不可/DM不可/問い合わせ不可の記載が見当たらない
- チェーン/FC/多店舗ブランドではなさそう
- 人間確認後すぐ送信できる可能性が高い

### 条件付き候補

条件:

- 個人店らしいが、営業不可表記や連絡導線の確認が一部未完了
- Instagramのみ確認済み
- 公式サイトはあるが問い合わせ導線が弱い
- 人間確認後に送信判断が必要

### 新規候補

条件:

- Web補助リサーチで見つけた候補
- まだ `data/prospects/*.json` やスプレッドシートに入っていない
- 先にJSON追加が必要

### 除外・後回し候補

条件:

- チェーン/FC/多店舗ブランド
- 本部運営色が強い
- 総合SNSしかない
- 連絡導線がない
- 営業不可/DM不可/問い合わせ不可
- 実在確認が弱い

### 候補不足

10件に満たない場合は、なぜ不足したかを具体的に記録する。ただし、Web補助リサーチを行わずに即0件で終了しない。

## 出力

以下の形式で出力する。

1. 今日の営業候補10件
2. 各候補の店名、業態、地域
3. 個人店・小規模店らしい理由
4. 連絡導線
5. 送信前確認URL/SNS
6. DM文面案
7. メール件名案
8. メール本文案
9. 送信後のステータス更新案
10. 今日の推奨送信順

## 重要ルール

- Markdown保存は行う
- 営業送信は行わない
- Googleスプレッドシート更新は行わない
- `scripts/sheets/send-prospects.mjs` は実行しない
- `SECRET_TOKEN`、Webhook URL、APIキー、認証情報は記載しない
- 架空URLや架空情報は使わない
- 不明情報は `未確認` と書く
- 候補の質が低い場合は無理に10件出さず `候補不足` と記録する
- ただし、既存JSONだけを見て即0件で終了せず、Web補助リサーチまで行う

## 文面ルール

- ICHI Socialの営業入口は「無料簡易SNS診断」にする
- 架空の実績、導入社数、成果保証表現は使わない
- 「必ず集客が増える」「フォロワーが増える」などの断定表現は使わない
- 整体・健康系では医療効果を断定しない
- 飲食店では予約導線を営業連絡に使えるか慎重に確認する
- 美容系では成果保証・集客保証を避ける

## 0件防止と補完判定

毎日12:00の日次営業候補生成では、候補0件を成功扱いしない。ファイル存在だけでは完了扱いにせず、Markdown本文またはJSON内の候補件数を必ず確認する。

### 新しい成功条件

- 目標はA/B候補10件
- 最低でもA/B候補8件以上を実用候補として出力する
- 8件未満は `候補不足` として補完対象にする
- 0件は `失敗/未達` として扱い、`emergency_refill_mode` を実行する
- 日次営業対象にはA/Bのみ含め、C/除外候補は参考記録に分ける

### 候補数別の判定

- 0件: 失敗/未達。緊急補完提案または緊急補完を行う
- 1〜7件: 候補不足。探索Tierを広げて補完する
- 8〜9件: 実用可。ただし補完候補を追加で探す
- 10件以上: 完了

### 探索Tier

通常探索で10件に満たない場合、以下の順番で探索範囲を広げる。

1. Tier 1 業種拡張: ボディケア、小規模エステ、サウナ/温浴、スポーツスクール、キッズスクール、料理教室、花屋、雑貨店、セレクトショップ、ベーカリー、テイクアウト専門店、小規模宿泊、地域密着施工会社、採用に困っていそうな中小企業
2. Tier 2 エリア拡張: さいたま市全域、川越、所沢、志木、新座、ふじみ野、三郷、八潮、春日部、松戸、柏、市川、船橋、浦安、千葉市、横浜市北部、川崎市、東京23区全域
3. Tier 3 フォロワー条件の近似許容: フォロワー数不明でもInstagram URLあり、小規模事業者らしい、改善余地あり、5,000人以上と断定できない候補はB候補にする
4. Tier 4 近接条件の候補: Instagram運用、投稿頻度、プロフィール導線、ハイライト、予約/問い合わせ導線、投稿設計に改善余地が明確な候補をB候補にする

### emergency_refill_mode

0件の場合は `emergency_refill_mode` に切り替える。

- CSVがなくても中止しない
- `CSV未設置のため完全照合未実施` と明記する
- ローカルJSON、既存レポート、台帳で最大限重複除外する
- フォロワー数不明はB候補として許容する
- `instagramFollowers: null`、`followerSegment: "unknown"`、`fitScore: "B"`、`instagramSalesPriority: "B"` とする
- `fitReason` に `フォロワー数未確認のためB。人間検収で5,000人未満確認が必要` と明記する
- 最低8件、目標10件を出力する
- Sheets投入、営業送信、Instagram DM、コメント、フォーム送信は行わない

### 補完チェックの判定

12:30 / 14:00補完チェックでは、当日JSON、当日レポート、候補件数、A/B候補数、C/除外混入、重複候補の有無を確認する。ファイルが存在するだけでは成功扱いにしない。

### レポート必須項目

候補数、A候補数、B候補数、C/除外候補数、フォロワー5,000人未満確認済み件数、フォロワー数不明件数、Instagram URL確認率、重複除外件数、使用した探索Tier、候補不足の有無、候補不足時に試した拡張条件、CSV有無、Sheets投入していないこと、営業送信していないこと、人間検収で確認すべきことを記録する。

## Agent Operations Dashboard更新

作業開始時に `scripts/agent-status/update.mjs` で該当タスクを `running` にする。候補数に応じて終了時のstatusを更新する。

- 候補10件以上: `success`
- 候補8〜9件: `partial`
- 候補1〜7件: `needs_review`
- 候補0件: `blocked`

notesには `Google Sheets投入なし`、`営業送信なし` を残す。秘密情報、認証情報、Webhook URL実値、Cookie、SNSログイン情報はstatus JSONに入れない。

## Agent Status更新ルール

このプロンプトを実行する際は、`docs/ops/agent-status-prompt-footer.md` のルールに従うこと。

- 作業開始時に `scripts/agent-status/update.mjs` で `running` を記録する
- 主要フェーズ完了時に `phase` / `progress` を更新する
- 候補0件は `success` にしない
- 候補数に応じて `success` / `partial` / `needs_review` / `blocked` を設定する
- 作業完了後に `npm run agent:status:validate` と `npm run agent:status:render` を実行する
- 秘密情報はstatus JSONに入れない
